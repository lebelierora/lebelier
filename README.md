# るべりえ テイクアウト注文（lebelier）— 公開版サイト

飲食店「るべりえ」の自作モバイルオーダーの公開版（実装テスト段階）です。
静的サイト（GitHub Pages 想定）＋ Firebase Firestore で動きます。ビルドツールは不要です。

- お客さん用：`index.html`（テイクアウト注文＋注文状況）
- 厨房用：`kitchen.html`（受付画面）
- 注文データ：Firestore コレクション `takeoutOrders`／要注意リスト `blockedPhones`
- 通知音声：`audio/moko-order-v2.mp3`（モコの声「ご注文が入りました！」）、`audio/moko-call-v2.mp3`（呼び出し用に同梱・現状は未使用）

> 全ページに「テスト公開中」の表示を入れています。本番告知前の段階です。

## ファイル構成

```
index.html            お客さん用ページ（トップ／注文／詳細／注文手続き／完了／注文状況を1ページで切替）
kitchen.html          厨房用 受付画面（PINゲート付き）
css/style.css         共通スタイル
js/firebase-config.js Firebase 初期化（ウェブ用 config は公開前提の識別子。保護はルール側で行う）
js/menu.js            メニュー16品のデータ＋日時・料金ユーティリティ（Asia/Tokyo 基準）
js/customer.js        お客さん側ロジック
js/kitchen.js         厨房側ロジック（厨房PINはこのファイル冒頭の定数）
audio/                モコの通知音声
firestore.rules       Firestore セキュリティルール（テスト段階の叩き台）
```

## デプロイ手順

### 1. GitHub Pages に置く

デプロイ先リポジトリ名は **lebelier** を予定しています。

1. GitHub でリポジトリ `lebelier` を作成し、このフォルダの中身をそのまま push する
2. リポジトリの Settings → Pages → Source を「Deploy from a branch（main / root）」にする
3. 公開URL（例：`https://<アカウント>.github.io/lebelier/`）で `index.html` が開くことを確認
4. 厨房画面は `<公開URL>/kitchen.html`

### 2. Firestore ルールを反映する

1. Firebase コンソール → プロジェクト「ruberie-order」（設定上の識別子）→ Firestore Database → ルール
2. `firestore.rules` の内容を貼り付けて「公開」を押す

### 3. 動作確認

1. お客さん用ページからテスト注文を送信（確認待ちで保存される）
2. 厨房画面を開き、PIN で入って注文が表示されること・音が鳴ることを確認
3. 「この時間で受付」→ お客さん側の完了画面／注文状況が「確定」に変わることを確認

## 厨房画面の保護について（重要）

- テスト段階の厨房画面は **簡易PINゲート** で守っています。テスト用PINは厨房用コード冒頭の定数で、値は店の電話番号の下4桁です（ここには書きません。運用担当者のみで共有してください）。
- PIN はクライアント側の簡易チェックであり、本格的な認証ではありません。あわせて Firestore ルールもテスト段階では緩く設定しています。
- **本番運用の前に、厨房側を Firebase Authentication（メール/パスワード認証）へ移行し、ルールを締めること**（具体的な締め付け項目は `firestore.rules` のコメントに記載）。

## 実装済みの仕様（試作で固めた内容）

お客さん側：
- メニュー16品（ホール6／揚げ6／スイーツピザ2／サイド2）、カテゴリタブ、商品固有トッピングで価格変動、数量は最大20
- カット／包装（ホール・スイーツのみ）：4カット⇔箱は同時選択不可（箱はカットなしのお渡し）。レモンバターシュガーは箱を選べない
- 受け取り日は今日から7日先まで（テスト拡張。木曜は定休日で枠なし）、日付は「2026年11月25日（水）」形式のチップ選択
- 受け取り時刻は10分刻み。最短リードタイムは合計点数で段階制（1〜4点=30分／5〜9点=40分／10点以上=60分）。最終枠は月〜土19:30・日曜17:30
- 名前・電話番号必須、備考任意。お支払いは受け取り時にレジで（現金・PayPay・コハクペイ等）
- 送信後は「確認待ち」。完了画面はリアルタイム更新され、確定・時刻変更がそのまま表示される
- 注文状況は受け取り日＋電話番号で確認（氏名は表示しない）。名前・電話番号は端末に記憶して次回自動入力
- 要注意リストに登録された電話番号からは注文できない（電話注文への案内を表示）

厨房側：
- 注文をリアルタイム表示。受け取り時刻が主役の大カード、未受付は赤点滅、確定後は「あと○分で受け取り」
- 未受付・対応中の件数サマリーを常時表示。件数に応じて表示密度を自動調整。完了分は折りたたみ
- 受付時は確定予定時刻を −5分／+5分／最短ボタンで調整でき、希望との差分を表示
- 「お渡し済み」で完了。「来店なし」で要注意リストへ電話番号を登録（解除も可能）
- お客さんの過去の来店回数から「初めての方／ご注文○回目／⭐常連さん」バッジを表示
- 新着時はモコの音声で通知（「音を有効にする」ボタンで有効化、未受付がある間は繰り返し再生）
